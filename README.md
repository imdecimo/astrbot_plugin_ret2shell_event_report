# AstrBot Ret2Shell 赛事播报插件

对接 [Ret 2 Shell](https://github.com/XDSEC/ret2shell)（回归终端）的赛事事件推送 WebSocket API，把 CTF 比赛现场发生的事实时播报到群里。

| | |
| :--- | :--- |
| 插件版本 | `1.3.1` |
| 要求 AstrBot | `>= 4.17.0` |
| 支持平台 | `aiocqhttp`、`qq_official` |
| 仓库 | <https://github.com/imdecimo/astrbot_plugin_ret2shell_event_report> |

## ✨ 功能特性

- 🚩 **实时赛事播报**：题目上/下线、一二三血、里程碑达成、新通知、作弊预警、队伍反馈等
- 📊 **信息查询**：赛事信息 (`/game`)、积分总榜 (`/rank`)、题目详情 (`/challenge`)、队伍详情 (`/team`)
- ⏰ **赛程定时播报**：比赛开始/结束时自动推送带赛事名称的通知
- 🔔 **三级播报分类**：公开 / 管理 / 运维事件分别推送到不同目标
- 🔌 **重连退避**：WebSocket 断开后按 1s→2s→…→60s 指数退避重连，不会空转打服务端
- 🧩 **通知补偿**：配置账号后，断线或停机期间遗漏的比赛通知会在恢复后自动补播，不重不漏
- 🎛️ **事件开关**：16 类事件可在 WebUI 里逐项勾选
- ⚙️ **全 WebUI 配置**：所有配置项都在 AstrBot 管理面板里改，不用碰代码

## 📦 安装

在 AstrBot 管理面板的 **插件市场** 搜索 `Ret2Shell`，或按下面任一方式手动安装：

- **从链接安装**：在「已安装」或「插件市场」页面点击右下角的 **安装插件（+）**，选择「从链接安装」，填入本仓库地址
  `https://github.com/imdecimo/astrbot_plugin_ret2shell_event_report`
- **从文件安装**：从作者处获取 `.zip` 安装包，同一入口选择「从文件安装」

安装后回到「已安装」页面确认加载状态。如果显示加载失败，去 **数据与日志 → 日志** 看具体报错。

本插件依赖 `websockets >= 12.0` 和 `httpx >= 0.24.0`，已写在插件目录的 `requirements.txt` 里，AstrBot 安装插件时会自动读取并安装。如果自动安装失败（例如 AstrBot 运行环境访问不了 PyPI），可在 **数据与日志 → 日志** 页面用「安装 Pip 库」手动补装 —— 注意要装到 AstrBot 实际运行的那个 Python 环境里，Docker 部署时不要只装在宿主机上。

## ⚙️ 配置

安装后在「已安装」页面点击插件卡片上的 **配置** 即可填写。

| 配置项 | 必填 | 默认 | 说明 |
| :--- | :---: | :--- | :--- |
| `ret2shell_ws_link` | ✅ | 空 | Ret2Shell 平台提供的 WebSocket 连接地址 |
| `public_umo` | ❌ | `[]` | 公开事件的推送目标 |
| `admin_umo` | ❌ | `[]` | 管理事件的推送目标 |
| `ops_umo` | ❌ | `[]` | 运维事件的推送目标 |
| `ret2shell_account` | ❌ | 空 | Ret2Shell 平台账号，填了才解锁 `/challenge` 与通知补偿 |
| `ret2shell_password` | ❌ | 空 | 与账号配套的密码，**必须与账号同时填写才生效** |
| `enabled_events` | ❌ | 全部开启 | 逐项勾选要接收的事件类型（见[事件开关](#-推送事件类型与开关)） |

三个 UMO 列表都留空插件仍能正常连接，只是不会往外发消息。

### 获取 WebSocket 链接

在 Ret2Shell 的 **比赛管理 → 赛事播报（Event API）** 页面复制连接地址，形如：

```
wss://<你的部署域名>/api/event/connect?game_id=42&token=<game_token>
```

> ⚠️ 链接里的 `token` 是**赛事级凭据**，拥有它就能接收该场比赛的全部事件。请只发给可信的人，泄露后可在同一页面点「重新生成」使其失效。插件在日志和 `/ret2shell_status` 输出里对 `token` 做了脱敏（显示为 `***`），但配置文件中仍是明文，请自行保管。

### 填写推送目标（UMO）

UMO 是 AstrBot 的会话标识，格式为：

```
平台适配器名:消息类型:会话ID
```

例如 `aiocqhttp:FriendMessage:123456789`、`aiocqhttp:GroupMessage:987654321`。在 AstrBot 管理面板的会话管理页面可以看到当前活跃会话的 UMO，也可以通过 `GET /api/v1/sessions/active-umos` 接口获取。

一个列表里可以填多个目标，插件会逐个推送：

```json
["aiocqhttp:GroupMessage:987654321", "aiocqhttp:FriendMessage:123456789"]
```

### 关于平台账号

账号与密码**留空即按匿名只读模式运行**，`/game`、`/rank`、`/team` 三个查询命令依然可用。

填写账号后可以额外获得：

- `/challenge` 题目详情查询
- 断线 / 停机期间的比赛通知补偿（见[消息补偿说明](#-消息补偿说明)）

几点需要注意：

- **只填其中一个不会生效**，插件会按匿名模式运行并在日志中给出警告。
- 该账号必须是**本场比赛的管理员**，也就是持有该场比赛 WebSocket 链接的那个账号；否则访问题目和通知接口会返回 403。参赛者账号无法用于播报。
- 密码在配置界面中**以掩码显示**，但底层仍以**明文**保存在 AstrBot 的配置文件中，请自行评估风险。
- ⚠️ 平台对密码错误有计数：累计 **5 次**失败会导致该账号被**冻结 30 分钟**。请先确认密码无误，不要靠反复重试来排错。

### 播报级别

| 级别 | 包含事件 | 配置项 |
| :--- | :--- | :--- |
| **公开** | 题目上/下线、一二三血、里程碑、新通知、比赛冻结/解冻、比赛开始/结束 | `public_umo` |
| **管理** | 普通解题、作弊检测、过快提交、队伍题目反馈 | `admin_umo` |
| **运维** | 集群超载、集群恢复、服务崩溃 | `ops_umo` |

## 📨 推送事件类型与开关

`enabled_events` 里勾选的就是下表第一列的 key。**比赛开始 / 结束不受开关控制**，由本地定时器在赛程时刻直接推送。

| 开关 key | 消息 | 级别 |
| :--- | :--- | :--- |
| `challenge_up` | ⬆️ `[方向] 新题目上线：题目名` | 公开 |
| `challenge_down` | ⬇️ `[方向] 题目下线：题目名` | 公开 |
| `new_hint` | 💡 `[方向] 题目名 发布了新提示` | 公开 |
| `blood_1` | 🥇 `恭喜 队伍 获得 [方向] 题目 一血！` | 公开 |
| `blood_2` | 🥈 二血 | 公开 |
| `blood_3` | 🥉 三血 | 公开 |
| `correct` | ✅ `队伍 解出了 [方向] 题目` | 管理 |
| `cheated` | 🤥 检测到作弊，显示抄袭者与被抄袭者 | 管理 |
| `too_quick` | 💥 队伍提交过快 | 管理 |
| `chat_message` | ✉️ 队伍向管理员提交的题目反馈 | 管理 |
| `new_notification` | 📢 `新通知：标题` | 公开 |
| `freeze` / `unfreeze` | 🧊 比赛已冻结 / 🌊 比赛已解冻 | 公开 |
| `cluster_overloaded` | ⚠️ 集群超载 | 运维 |
| `cluster_recovered` | ✅ 集群恢复 | 运维 |
| `server_panic` | 🔥 服务崩溃 | 运维 |
| *（无开关）* | 🚀 / 🏁 比赛开始 / 结束 | 公开 |

> 里程碑达成（`🏅 队伍 达成里程碑：名称`）会追加在所属解题消息里，**级别跟随该条消息** —— 一血 + 里程碑进公开群，普通解题 + 里程碑进管理群。

> ⚠️ **从 1.2.x 升级的用户请注意**：`chat_message`（队伍题目反馈）是 1.3.0 新增的开关，你已保存的配置里不会有它，需要手动勾选一次才会开始播报。默认不勾是为了避免队伍发给管理员的私密反馈被误推到公开群。

## 🧩 消息补偿说明

Ret2Shell 的 WebSocket 是**纯推送、无回溯**的：客户端连上后只能收到连接之后产生的事件，断线重连不会补发，协议里也没有「从某个位置重放」的参数。因此**断线期间的绝大部分事件会永久丢失** —— 这不是插件能绕过的限制。

本插件能做的补偿有限，请按下面的范围预期：

| 事件 | 可补偿 | 说明 |
| :--- | :---: | :--- |
| 📢 新通知 (`new_notification`) | ✅ | 配置账号后按通知 id 比对补播，不重复也不遗漏 |
| 其余全部事件 | ❌ | 服务端没有提供可按时间增量拉取的公开接口，无法对账 |

通知补偿的工作方式：

- 以 REST 通知列表为唯一事实来源，按 `id` 去重，因此**不会重复播报**
- 已见通知 id **落盘保存**在 AstrBot 的插件数据目录 `data/plugin_data/<插件名>/notification_state.json`（按比赛 id 区分），重启后沿用上次运行的事实而不是重新快照。这是插件**唯一**允许的落盘位置：若取不到该目录（权限等原因），插件会**放弃落盘**、只把状态留在内存里，并在日志中说明；此时通知照常播报，但重启后无法补播停机期间的通知
- 触发时机：**启动时追平停机期间的通知**、WebSocket 重连后、收到新通知事件时、以及每 60 秒定时对账一次
- 定时对账是为了兜住某次请求失败的情况，保证最终能补上
- **首次运行**（没有状态文件，或换了另一场比赛）没有历史参照，此时把启动瞬间的通知列表全部视为历史、不播报，避免刷屏
- 长期停机后重启时，若待补通知超过 10 条，只重建基线而不补播，并在日志中说明
- 若状态既没落盘、启动时也拉不到通知列表（自动重试 3 次），插件会退回「收到即播报」模式：**通知不会漏**，但暂时没有去重能力；一旦某次对账成功即自动恢复去重

> 状态文件是纯运行时数据，存放在 AstrBot 的 `data` 目录下（不在插件自身目录里，因此插件更新/重装不会丢）。删掉它只会让插件把当前通知列表重新当作基线，不影响其他功能。

对于无法补偿的事件，插件会在重连时用 `warning` 级别日志写明断线时长，便于赛后核对播报记录是否完整：

```
🔁 已重连，断线约 12.3 秒；该时段内除通知外的赛事事件无法补发
```

## ❓ 常见问题

**Q：`/challenge` 提示「该功能需要登录权限」**
没配置平台账号。填上 `ret2shell_account` 和 `ret2shell_password`（两个都要填），然后重载插件。

**Q：`/challenge` 提示「权限不足」**
两种可能：配置的账号不是**本场比赛的管理员**；或者比赛正处于**冻结期**、题目尚未发布 —— 服务端在这两种情况下都会拒绝访问题目详情。

**Q：`/challenge` 提示「比赛尚未开始」**
服务端返回 412，比赛开始前无法查询题目详情。

**Q：队伍反馈（`chat_message`）没有播报**
先确认 `enabled_events` 里勾了 `chat_message`。从 1.2.x 升级上来时它默认不在你的配置里（见上方升级提示）。

**Q：重启插件后补播了一堆通知，正常吗？**
正常，这是停机期间的补偿。如果待补通知超过 10 条，插件只会重建基线而不补播，避免刷屏。

**Q：怎么确认鉴权 / 补偿有没有生效？**
发 `/ret2shell_status`。它会显示平台鉴权是否启用、通知补偿是否启用（已记录多少条通知）、状态是否能落盘、当前 WebSocket 状态、以及赛程时间。

**Q：断线期间的事件能补回来吗？**
只有通知能。其他事件类型服务端不提供增量拉取接口，无法对账 —— 详见[消息补偿说明](#-消息补偿说明)。

**Q：填错密码被锁了怎么办？**
等 30 分钟自动解冻。期间不要继续尝试，否则计数不会清零。

**Q：比赛开始/结束的播报没出现？**
这条播报由插件**启动时**读取的赛程时间驱动，只在启动时排一次。如果插件是在比赛开始后才启动，或者中途改过赛程，就不会补发。重载插件可以重新排期。
